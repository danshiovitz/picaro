When the travel button is pressed, the client enters route selection mode. The cursor should turn to a boot (like the icon that's on the button). A card appears in the play section that says "Travel" as the title and the body shows their current route, like "C3 - C2 - D2" (this may need to wrap lines). Initially the route is just their current location. When they're in route selection mode like this, if they click on a hex that is adjacent to the last element in the route it adds it to the end of the route. If they click on a hex that is already part of the route, it erases from the end of the route back to that element (but not including it, so if they click on the starting hex the route becomes a single element). If they click on a hex that is not adjacent and not part of the route, it acts as though the player had clicked on every hex on the shortest path between the end of the route and the clicked-on hex, so it adds multiple elements to the path. The route should also be displayed visually on the map as a series of line segments drawn in a bright color. Beneath the travel card in the play area are buttons labelled "Go" and "Cancel". Clicking on cancel drops out of route selection mode (turning the cursor back to normal and clearing the play area). Clicking on Go exits out of travel mode and does a call to the backend saying the player travels along the given route. The response from the backend This should update the location on the backend to the last element in the route, and decrement the player entity's turn count by 1. It should return something to the client indicating that the player entity's location has changed to the new value and turn counter has changed to the new value. The backend should validate each step in the route, that the first step is the player's location and each successive step is adjacent to the one before it. If that's not the case, it should return a "rule violation" error in its response saying there are gaps in the route. If the route is longer than 4 elements, it should return a "rule violation" error saying the travel route is too long. If the backend returns this rule violation error, the client should put a card in the play error labelled "Travel Error" showing the error message.In all cases (not just travel), if there is anything in the play area, all the action buttons should be disabled - greyed out and not doing anything if clicked on.
